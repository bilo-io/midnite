# Getting started

Midnite ships as a single desktop app for macOS (Apple Silicon), Windows,
and Linux. Install it — one command on macOS — open it, and you're running — the app
bundles everything it needs (the local [gateway](/) and the UI) and runs entirely
on your machine. There's no server to stand up and no data that leaves your
device except the agents' own calls to their model provider.

On first launch the app asks you to create a local sign-in. That account lives
only in your own `~/.midnite` folder — nothing is sent anywhere, and there's no
Midnite service to sign up for. It exists because the app generates a real
encryption key on first run to protect the provider API keys it stores, and a
lock screen is what keeps that data behind something.

The rest of this page walks you from download to a running agent in a few minutes.

## What you'll need

- A supported machine: **macOS (Apple Silicon)**, **Windows (x64)**, or **Linux (x64)**.
- An **agent CLI** installed and on your `PATH` — Midnite drives coding agents like
  Claude Code rather than shipping its own. You'll point Midnite at it under
  [Settings → Agents](/settings/settings).
- A **model-provider account** for whichever agent you use (e.g. an API key), so
  the agent can actually call a model.
- A **git repository or two** you want agents to work in — registered under
  [Settings → Repos](/settings/settings).

## Install

### macOS (Apple Silicon) — one command

Paste this into a terminal:

```bash
curl -fsSL https://midnite-app.vercel.app/install.sh | sh
```

It downloads the latest release, installs it to `/Applications`, links the
`midnite` CLI onto your `PATH` when it can, and launches the app — with **no
Gatekeeper warnings**. (The builds aren't notarized yet; installing with `curl`
means macOS never quarantines the app, unlike a browser download.) **Re-run the
same command any time to update.**

> Intel Macs aren't supported in the current release — the macOS build is Apple Silicon only.

### Windows and Linux

Download the build from the [releases
page](https://github.com/bilo-io/midnite-app/releases/latest):

| Platform | File |
| --- | --- |
| Windows (x64) | `midnite-<version>-x64.exe` |
| Linux (x64) | `midnite-<version>-x86_64.AppImage` |

## First launch

- **macOS** — installed via the command above, the app just opens. If you instead
  downloaded the `.dmg` in a browser, macOS quarantines it and blocks the first
  launch ("Apple could not verify…") — and on macOS 15+ the old *right-click →
  Open* trick no longer works. Either allow it under **System Settings → Privacy
  & Security → Open Anyway** after the blocked attempt, or clear the quarantine
  flag:
  ```bash
  xattr -dr com.apple.quarantine /Applications/Midnite.app
  ```
- **Windows** — the installer is unsigned, so on the SmartScreen prompt click
  **More info → Run anyway**.
- **Linux** — make the AppImage executable, then run it:
  ```bash
  chmod +x midnite-*.AppImage
  ./midnite-*.AppImage
  ```

### Creating your sign-in

The first screen is a sign-in. Choose **Sign up** and create an account with any
email and password — it's stored locally in your own `~/.midnite` database, not
registered with any service, so use whatever you like. You can also sign in with
GitHub if you'd rather not manage another password.

On first run Midnite creates its data folder at **`~/.midnite`** — one shared
home per machine, used by the desktop app, the bundled CLI, and `midnite serve`
alike. Your tasks, sessions, and settings live there in a local SQLite database
(`~/.midnite/midnite.db`), alongside `midnite.json` (settings) and `.env` (the
generated secrets). Everything stays on your machine, and you can back it up or
move it from [Settings → Data](/settings/settings).

## Set up your workspace

The first time you open the app it offers a short setup wizard. You can also do
these by hand in [Settings](/settings/settings):

1. **Agents** — choose the CLI and provider that will run your tasks, and set how
   many tasks may run in parallel. Turn on **autonomous scheduling** here if you
   want Midnite to pick queued tasks up on its own — with it off, a task only
   starts when you open a terminal for it yourself.
2. **Repos** — register the git repositories agents are allowed to work in.
3. **Safety** — pick an autonomy mode and the guardrails that go with it, so you
   decide how much an agent can do on its own.

Then create your first bit of work:

1. Open **[Projects](/app/projects)** and create a project (optionally let AI
   expand a rough description into a plan).
2. Add a **[task](/app/tasks)** — describe what you want done and pick a repo. The
   scheduler hands it to an agent automatically.
3. Watch it run in **[Sessions](/agents/sessions)**, and review the pull request it
   opens right from the task card.

## Next steps

Once you're up and running, each feature has its own page:

- **[Projects](/app/projects)** and **[Tasks](/app/tasks)** — organise work and put
  agents to it.
- **[Sessions](/agents/sessions)** — watch an agent run in a live terminal.
- **[Memory](/agents/memory)** — give agents durable context so they stop
  rediscovering your conventions every run.
- **[Ops](/overview/ops)** — track fleet health, spend, and the periodic
  [digests](/overview/digests).
- **[Settings](/settings/settings)** — point Midnite at your repos, pick the agent
  CLI, and set safety guardrails.

Power users can also drive everything from the terminal — see the CLI on the
**[Overview](/)**.
